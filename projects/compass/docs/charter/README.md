# Compass Charter

The first substantive Compass document should be named `compass-vision-and-scope-charter.md` and stored here.

The charter establishes shared intent before requirements, MVP boundaries, Skill specifications, or testing. It should record vision, problem, users, outcomes, scope exclusions, operating principles, assumptions, constraints, success signals, roles, and open questions.

## Intake options

Dexter can begin in either of two ways:

1. **Guided interview:** Dexter asks a structured series of focused questions and periodically confirms its summaries with the user.
2. **User-provided vision:** The user places an existing file in [`source-material/`](source-material/). Dexter extracts candidate charter content, preserves traceability to the source, and asks follow-up questions for gaps or ambiguity.

The two options may be combined. Source material remains unchanged; the charter is a separate, user-approved synthesis.

## Separation from test artifacts

The project-local [`skill-exchange/`](../../skill-exchange/) is only for exact Skill packages handed to or received from Copilot Cowork. Vision notes and other charter inputs belong in this documentation area, not in the Skill exchange.

A charter is not evidence that a proposed capability works and must not contain fabricated test outcomes.
